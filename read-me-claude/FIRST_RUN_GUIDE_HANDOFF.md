## What changed

- Home keeps its full layout. After the first owned agent has arrived and the birth card has been acknowledged, a small pointer introduces the actual character. Next points to the actual kitchen table; tapping the character opens the real conversation instead.
- The table opens its existing sheet or desktop rail. The pointer identifies the existing Watch button, with no duplicate Watch action. Watching enters the actual live game, where a final pointer explains the shared cards and the spectator role. A new agent can arrive to a quiet kitchen: that branch closes the sheet and points to the real casino door. Entering the casino does not deploy or seat anyone. The shared-card hint waits for a real Watch view, including the desktop casino.
- Skip is always available. The first display writes an owner-wide browser record, so completion, dismissal, an interrupted reload and another agent do not restart it. Valid records from the previous practice flow are migrated. Progress during this visit survives the phone chat transition. Changing owner clears it; retiring its agent ends it.
- Pointers sit outside layout flow, preserve focus and leave their highlighted controls clickable. They follow viewport changes, room scrolling and character motion. Card highlights enclose the actual five card slots. Human play, read sheets, session ceremonies and chat overlays take precedence.
- No notebook, inventory, newspaper, needs rule, economy change or poker pacing change is included. A proposed room object needs a useful function, interaction and placement before implementation.

## Review and limits

Actual built phone and desktop review is part of this loop. The first screenshot pass found an overly wide card outline and a duplicated Watch action; both were corrected. The real fresh-birth check then exposed an incorrect assumption: one new agent does not necessarily have a kitchen game to watch. The quiet branch now points to the casino rather than ending at a table with no game. Normal-speed guest testing also exposed a retained welcome-page scroll position after birth: the explicit Go home transition now aligns the actual room after it renders, without having tooltips scroll the page or interrupt later reading. The guide uses one short sentence per step and avoids a separate lesson or permanent tutorial navigation.

Persistence is local to this browser and owner. With browser storage blocked, the provider remembers the visit; a fresh browser process cannot retain that record. Automated and local playtests establish behavior and layout, not newcomer comprehension or desire to return. Those remain the next human playtest's success criteria.
